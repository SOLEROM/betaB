# STM32F722

## What It Is

The **STM32F722** is an ARM Cortex-M7 microcontroller from
STMicroelectronics. In the Betaflight ecosystem it is one of the most
common "F7" flight controller MCUs and the entry-level F7 target — a
balance of performance and cost that sits between the F4 workhorse
([[STM32F405]]) and the high-end H7 family ([[STM32H743]]).

## Why It Matters to Betaflight

- It is one of the **handful of MCUs Betaflight actively supports**
  (alongside F405, F411, F745, F765, G4XX, H7XX, AT32F435). (Source:
  [[Betaflight Manufacturer Design Guidelines]], confidence: **high**.)
- It has **hardware UART signal inversion**, removing the need for
  external inverters used on F4 boards to support FrSky SBUS / SmartPort.
  (Source: [[Oscar Liang FC Processors]], confidence: **high**.)
- It is **pin-compatible with the F405**, which let manufacturers reuse
  existing F4 board layouts when upgrading to F7. (Source: [[AnyLeaf
  Quadcopter MCU Comparison]], confidence: **medium**.)
- Its 512 KB flash is **the binding constraint** that motivated the
  Betaflight [[Cloud Build System]] in BF 4.4. (Source: [[Oscar Liang
  Betaflight 4.4]], confidence: **high**.)

## Key Specifications

| Spec | Value | Source |
|------|-------|--------|
| Core | ARM Cortex-M7 (single core) | ST datasheet |
| Max clock | 216 MHz | Multiple |
| Flash | 512 KB (RET6) or 1024 KB (RGT6) | [[Betaflight Issue 197 Supported MCUs]] |
| RAM | 256 KB (incl. DTCM/ITCM tightly-coupled memory) | Oscar Liang |
| L1 cache | 4–16 KB I-cache + D-cache | ST AN4839 |
| Hardware UARTs | 5 (typical board mapping) | Oscar Liang |
| UART signal inversion | Yes (hardware) | Oscar Liang |
| SPI peripherals | Multiple, no F4-style DMA limitation on SPI1 | Oscar Liang |
| Package (BF context) | LQFP64 (R) | ST datasheet |

## Variants in the Wild

Two BF-relevant package/flash combos:

| Part Number | Flash | Use |
|-------------|-------|-----|
| STM32F722R**E**T6 | 512 KB | "Not recommended for new designs" per BF maintainers' draft list; the cloud build keeps it alive. (Source: [[Betaflight Issue 197 Supported MCUs]], confidence: **medium** — draft list, not formal policy.) |
| STM32F722R**G**T6 | 1024 KB | "Recommended for new designs" in the same draft list. (Source: same, confidence: **medium**.) |

The BF target name **`STM32F7X2`** (sometimes seen as `F7X2RE`) covers
both, with the `X` as a wildcard digit and `RE` denoting the smaller
flash variant. (Source: [[Flying Rabbit Creating BF Target]], confidence:
**high**.)

## Build-System Footprint

From `make/mcu/STM32F7.mk` in the Betaflight repository (confirmed via
search snippets, file not directly fetched; confidence: **medium**):

```
-DSTM32F722xx       # device define
stm32_flash_f722.ld # linker script (512 KB flash)
```

For 512 KB targets the build overrides the global `OPTIMISE_SPEED`
compiler setting to save ~50 KB of flash, trading some hot-path speed for
a buildable binary. (Source: [[Oscar Liang Betaflight 4.4]] / community
build notes, confidence: **medium** — needs direct source verification.)

## Motor-Output Limit

Effective late 2024, **new flight-controller designs using STM32F4 or
STM32F7 MCUs are limited to 4 motor outputs** by Betaflight policy. The
H7 family is required for >4 motors (octocopters, X8). (Source:
[[Betaflight Manufacturer Design Guidelines]], confidence: **high**.)
This affects the F722 directly: it is suitable for quadcopters and
hexacopters with 4 motors, but not for new larger frames.

## Trade-offs vs Neighbors

| Vs | F722 advantage | F722 disadvantage |
|----|----------------|-------------------|
| [[STM32F405]] | 216 MHz vs 168 MHz; hardware UART inversion; better SPI DMA | Smaller flash on RET6; more expensive |
| [[STM32F745]] | Cheaper; smaller die; widely available | Half the flash, less RAM |
| [[STM32H743]] | Cheaper; lower power | Half the clock (216 vs 480 MHz); 4-motor cap; less RAM; no longer recommended for new BF designs |

## Editorial Note

The F7 family is, as of 2026, **transitional**: every authoritative
source (ST community guidance, Betaflight manufacturer guidelines,
AnyLeaf, Oscar Liang) points to the H7 as the recommended next-gen for
new designs. The F722 lives on because (a) cloud build keeps the flash
limit manageable, and (b) existing F4-compatible board layouts upgrade
cleanly to it.
